# Gemini runtime seam probe (pane P63)

## Contract before implementation

- **Structural question:** Can one session-local stream of mixed 16 kHz PCM and engine updates be published through the existing `LiveSession` snapshot authority without changing the HTTP/UI contract?
- **Minimum primitives:** retained audio position (absolute samples), engine update (preview, committed/revised, terminal), stable meeting speaker ID, session publication state. The position binds words to the tape; the update carries the only new provider output; the speaker ID is the UI-visible identity key; publication state owns lifecycle and revisions. Remove any one and either time, identity, or lifecycle becomes ambiguous.
- **Invariants:** input frames are retained before provider work; committed rows have absolute ordered sample bounds and canonical speaker IDs; a revision changes an existing visible row rather than duplicating it; Stop settles to `final` or a visible failure; sessions cannot share engine state; the existing snapshot/event schema stays intact.
- **Assumptions / unknowns:** `LiveSession` may require sequential frozen prefixes and reject rolling rewrites. Exact engine word source, window policy, speaker continuity, live latency, quality, and spend are unmeasured pending the bake-off. Voiceprint extraction from committed Gemini intervals may need a separate measured design.
- **Falsifier:** a scripted preview, commit, relabel, and terminal revision cannot be represented by existing `LiveSession` calls and consumed by the unchanged poller shape; or Stop cannot expose a failed finalization without hanging.
- **Tool decision:** inspect `LiveSession` and the current runtime/publication path to find the smallest seam. Run a one-command throwaway state probe against `LiveSession`; its acceptance/refusal counts decide whether to reuse it. Then use offline TDD through the runtime's public methods. Run focused existing tests only if they can detect an actual HTTP/runtime contract break.

## Hypothesis

`LiveSession` remains the snapshot authority. A thin per-session adapter converts engine updates to its publication calls; all capture, storage, and route handling stays at the existing runtime boundary.

## Verdict (one-command probe)

`PYTHONDONTWRITEBYTECODE=1 $RT.venv/bin/python prototypes/gemini-runtime/probe_session_seam.py` printed full `LiveSession` state after each action: prepared S00 base commit 1/1 accepted; first diarized rolling update 1/1 accepted; later correction to the same rolling interval 0/1 accepted (`not_at_frontier`). Thus unmodified `LiveSession` cannot show later Gemini identity repair. Choose the narrow new operation that replaces labels and segment boundaries over an already-owned rolling interval while preserving its exact concatenated text. Keep `LiveSession` as state and snapshot authority; no separate session document. The operation must reject changed words and intervals it does not own. A separate narrow speaker registration call is needed because the old identity preparer is tied to a MOSS decode.

The probe is throwaway; remove its script after the verdict is in the design doc.

## Counter contract (lead requirement)

- **Structural question:** Can a harness distinguish provider calls, retries, failures, timing repair, audio sent, and cost for each meeting without reading transcript or audio content?
- **Minimum primitives:** session ID as owner; cumulative counters by call kind and error/retry code; clamped/dropped timing counts; sent audio seconds; USD cost. These are the facts that alter quality, spend, or failure interpretation; no transcript, speaker label, audio, API key, or provider request body belongs here.
- **Invariants:** additive nonnegative deltas; sessions isolated; readout is a copy; every provider call records the audio duration and cost once; error/retry code names are stable metadata. A cached call records no audio sent and no cost.
- **Assumptions / unknowns:** actual Gemini usage metadata and anomaly denominators arrive from the phase-2 adapter. The fake can prove accounting and isolation, not provider truth.
- **Falsifier:** two fake sessions with different usage/error events cannot produce separate content-free totals and per-kind/per-code counts.
- **Tool decision:** a one-command in-memory aggregation probe prints both meeting states and rejects negative deltas; then an offline runtime test verifies the same behavior through the public diagnostics method. This changes the engine factory interface by one reporting callback.
- **Verdict:** the probe printed isolated states for 2/2 sessions: rolling calls 2 vs terminal calls 1; only the first session had a 429 error/retry and 1 clamped / 2 dropped words; audio and cost remained 10 s / $0.03 vs 20 s / $0.02. The production-path fake test passed with copied readouts and a content-bearing code rejected. The throwaway script was removed.

The source prevents tail loss; requests provide speech evidence; scheduling gives a single owner per interval; registry stabilizes local labels; session handles display/lifecycle; voice observations bridge to cross-meeting names.

### Live cache stride-boundary correction

**Question:** Can a 60-second scheduled window still be read when accepted audio is between 10-second schedule boundaries? **Hypothesis:** the live cache needs window length plus one stride, 70 seconds. **Falsifier:** a scheduler-produced window begins before the retained cache at any accepted sample position. **Tool:** one-command production `FixedWindowScheduler` arithmetic probe at 60, 60.5, 69.5, and 70 seconds; an uncovered window changes the cache bound. **Full state:** at 60.5 seconds the requested window was 0–60 seconds but the old 60-second cache began at 0.5 seconds; at 69.5 seconds it began at 9.5 seconds. The 70-second cache covered all four positions. **Verdict:** set cache to 70 seconds (2.24 MB) while keeping the scheduler's 60-second window. A focused production-engine test blocks a rolling call, advances capture to 69.5 seconds, resumes the worker, and passes. The earlier 60-second cache probe was valid for size but insufficient for schedule coverage; this correction supersedes that cache-size conclusion. The Account 60-minute stage conclusion is unchanged.

## H1 product defects: turn spans, Stop tail, preview

**Structural question.** What must the public meeting surface own at each point in the audio clock so that a word stream becomes readable speaker turns, Stop has no unlabelled tail, and fast words are visible before rolling labels?

**Minimum primitives.** A word has text, local speaker and sample bounds. A turn merges adjacent same-speaker words with at most 1.5 s between bounds. The rolling frontier marks the last labelled sample; accepted samples mark the Stop target. `LiveSession` owns a revised prefix and a provisional suffix, which the public snapshot carries separately. A bounded Stop drain may extend the revised prefix before close. Each is needed: words preserve transcript content, turns cover speech between words, the frontier identifies the missing tail, and the provisional field is the prelabel text authority.

**Invariants.** Rolling and terminal turn text preserves all ordered words; a turn starts at its first word and ends at its last. Speakers do not merge across a speaker change or gap >1.5 s. A successful Stop drain revises through accepted samples before `session_closed`; failure/deadline retains the existing empty-base fallback and terminal path. Provisional publication starts at `committed_samples` and is observable through the public HTTP snapshot without changing its schema. Provider calls, errors, timing anomalies and spend remain content-free.

**Assumptions and unknowns.** The lead's H1 12-pass measurement used the H1 #3 accept6 truth set and reports settled/final DER .464568/.271687, 208/1216 reference seconds without a nearby settled word, and a 17–18 s settled tail. These numbers identify bugs, not predicted post-fix DER. Whether real diarize=False Gemini returns word annotations, whether the preview is published then hidden by polling, and whether the H1 latency probe counts the separate `provisional` field are unknown until tested. A 5-second word latency result is unmeasured after repair.

**Falsifiers.** A fake real-runtime rolling/terminal pass still yields one row per word or a gap larger than 1.5 s inside one turn. A paced Stop snapshot still has `canonical_through_sample < accepted_samples` after a successful drain. A real public snapshot with a fake fast source omits `provisional` text while accepted > committed; a real Gemini preview request produces no word annotations; or the 250 ms H1 probe sees provisional but still reports words equal to labels.

**Tool decision.** First use public-interface regression tests against the actual runtime snapshot for turn grouping, Stop drain and preview. A deterministic fake provider isolates composition and ordering; each RED changes one production seam. Read the H1 latency probe and use one PUBLIC 10-second provider request only if the fake path works yet real preview remains empty. Then use the pane 6.2 scorer for a paced public HTTP check, reporting exact calls/spend and leaving H1 aggregate re-score to pane 6.2.

### W3 product port contract

**Structural question:** how can an asynchronous Live TEXT socket publish provisional text promptly through the synchronous accepted-frame interface while leaving rolling/terminal audio authority unchanged?

**Minimum primitives:** one source-audio sample cursor; one bounded ordered send chain; one Live socket epoch with optional resumption handle; 5 s PCM replay buffer; one text-turn start bound; one latest interim/final preview state; one content-free usage reporter. The send chain keeps accepted frames in order, the replay buffer covers an uncertain consumed boundary, and the preview state replaces interims rather than appending duplicate visible text.

**Invariants:** accepted PCM enqueues without waiting for a remote call; physical audio sends (including replay and 2 s tail silence) are counted once each and priced at list $0.005/min as an estimate; at most three attempts per reconnect episode; errors and retries use stable metadata codes; a preview update publishes a suffix beginning at `committed_samples` and never changes the rolling transcript; socket failures cannot fail or erase the canonical meeting; close stops the socket worker. ## F3 terminal policy implementation contract

**Structural question.** A whole-call transcript can split one real voice into several local labels and can hallucinate words in silence. Which minimal audio evidence repairs these without merging alternating voices?

**Minimum primitives.** Timestamped Gemini words locate claims; same-label turns expose A-B-A exclusions; continuous attributed audio spans produce production WeSpeaker vectors; a label centroid supports cosine union; a voiced-frame mask rejects unsupported word times. Each carries distinct evidence. The final mapping to existing live IDs remains the runtime's overlap operation.

**Invariants.** One Gemini call for recordings <=30 minutes, overlapping chunks only beyond. Turns join at <=1.5 s. Eligible same-label spans join through <=0.6 s gaps, require >=2 s, cap at first three 10 s intervals as in the measured prototype. Pairs union in descending cosine at >=.65 unless any cross-group A-B-A pair has both gaps <=2 s. The mode-1 WebRTC 10 ms gate retains a word if any voiced frame intersects its padded +/-0.2 s interval. Rolling uses the same gate. Preserve text/times of kept words and one-owner sample line.

**Assumptions and unknowns.** The selected policy's .104860 accept6 DER used H1 #3 and exposed tune/test PCM overlap; fresh-response stability and real music remain uncertain. Production integration has no measured DER until the next H1 run.

**Falsifier and tool decisions.** Scripted A-B-A, cosine and silent-word cases must produce exactly the frozen mapping and drops. A <=30-minute request producing >1 Gemini call or a real-audio H1 regression above the nominated bound would falsify adoption. Use production WeSpeaker and WebRTC in a throwaway no-provider probe, then focused TDD tests, then one capped public-audio integration; no new threshold search.

**Public Javier F3 receipt and Stop follow-up.** The first paced 50 s H1 #3 replay showed public W3 preview in 50/50 second buckets (word p50 0.0 s on the coarse probe), final one turn and DER .019999, but settled DER .446 with a 30/50 s frontier because the 5 s Stop drain returned false. A second public replay is the falsifier for deadline improvement. These single-case DER figures are not population qualification.

## D-4 settled surface contract

**Structural question.** After ingress pauses, what work remains before accepted audio has a settled speaker-labelled surface, and how does a reader know when that work finishes?

**Minimum primitives.** Accepted end is the audio horizon; canonical/rolling frontier is the labelled horizon; last-ingress time distinguishes an idle capture from continuous speech; one session worker serializes Gemini calls. One pending unit means one final window can cover the uncovered suffix. The existing snapshot field carries that unit to H1 without a new public event.

**Invariants.** While active and frontier < accepted, `pending_work_items` is 1, including an in-flight call; it becomes 0 only after a full idle/Stop drain. An idle drain becomes eligible after S=10 s without new accepted audio; continuous frames reset the clock. The drain window ends at accepted, commits through it, and shares the single call worker. Its words retain the rolling gate, registry, observations and turn grouping. It neither closes the meeting nor changes Stop's bounded fallback.

**Assumptions/unknowns.** H1 pauses ingress for up to 30 s before Stop, so a 10 s idle detector plus observed 6-10 s window latency should settle in that limit; actual end-to-end H1 remains unmeasured until pane 6.2 reruns. Provider calls can exceed the remaining timeout, in which case H1 must report timeout rather than false settlement.

**Falsifier/tool decision.** A public snapshot reporting zero pending while accepted exceeds labelled frontier, an idle 20 s test staying uncovered after its final window, or a continuous-feed test initiating a full drain would falsify the design. Use a one-command in-memory frontier prototype, then TDD through runtime snapshots and engine calls; one paced public replay only if local tests cannot establish scheduler behavior.

**D-4 measured verdict.** The TDD public snapshot test first failed at pending=0 with accepted 32,000 and rolling frontier 16,000, then passed at pending=1. Empty base accounting through accepted still leaves pending=1 until a rolling revision succeeds. A compressed-clock runtime test kept pending during six continuing frames, then one idle window committed the whole 6 s while session status stayed active; a blocked 20 s window was promoted without a second call. The actual 1.0x Javier50 H1 collector waited 13.374 s (51 polls) before Stop: pending 1->0, frontier 30->50 s, immediate DER .446->settled .063999 against H1 #3, final .019999. ## Growing-context scheduler contract

**Structural question.** How can one session use longer recent context to stabilize Gemini-local labels while each new call owns only the newly accepted frontier, without queuing stale windows when call latency exceeds the stride?

**Minimum primitives.** Accepted sample end chooses the latest stride tick; `Lmax` bounds context start; one in-flight worker serializes provider calls; last requested tick counts skipped due ticks; a PCM cache large enough for `Lmax + S` supplies delayed requests. The registry already receives absolute words and window start, so it does not need a new interface.

**Invariants.** A scheduled call is `[max(0,t-Lmax),t]` at the latest S-aligned `t`, initial call at S, frontier `t`. Exactly one Gemini window call is active per session; after a slow call, missed ticks are skipped and counted, never queued. Idle and Stop windows end at the exact accepted sample, use at most `Lmax`, and share the worker. Cache covers the oldest start reachable before the next stride tick. Counters remain content-free and readable per session. Composition constants default S=10 s/Lmax=30 s until pane 6.1's C4 verdict; no CLI flag.

**Assumptions/unknowns.** The C4 winner is not yet frozen; a longer context can increase cost or change quality. The placeholder overlap registry can consume growing windows but its settled DER and identity count on product path are unmeasured. Provider latency up to 300 s context is measured in the continuity prototype, but this pane must still test request geometry and busy-tick accounting.

**Falsifier/tool decision.** A 300 s window cannot be read at a delayed tick, two provider calls overlap, a slow call queues all intermediate ticks, or skipped counts differ from the omitted S ticks. Prototype the arithmetic on a printed 10/20/50/300 s timeline, then write regression tests against real scheduler/engine interfaces, then compose the default constants. The C4 verdict alone changes those constants, not the interface.

**Measured scheduler verdict.** TDD geometry, cache and skip tests failed on missing growing scheduler, fixed 70 s cache, and absent usage counter, then passed. The product engine now reads a 300 s window at a delayed 310.5 s position from `Lmax+S=310 s` cache; a blocked t10 call at accepted35 s coalesces to t30 with t20 counted once as skipped and max concurrency 1. A growing S20/L30 idle probe ended at exact accepted45 s with windows [10,40] then [15,45]. These are no-provider production-path measurements. Composition defaults S10/L30, H0 pending C4; real quality and cost effects remain unmeasured until H1/voiceprint runs.

**Idle skip correction.** A blocked t10 call followed by an idle drain at accepted35 s initially reported zero skipped ticks, even though t20 was omitted. The regression failed first, then passed after using the same stride arithmetic for scheduled and idle windows. The focused scheduler/runtime test set is 30/30 green. The idle window substitutes the latest due tick; intermediate ticks count as skipped.
