## Probe 3 — failing-before / passing-after, in the gate

    $ /opt/homebrew/bin/npm --prefix frontend test -- src/capture/preBranchDefects.test.ts
    Test Files  1 passed (1)
         Tests  19 passed (19)

Each PRD defect is one pre-branch test asserting the broken behaviour concretely and one
current-client test asserting the correct contract, both through the same harness and the
same measured server fake:

  defect 1  capacity 429   pre-branch posts [0,1,2,3,4,5] and the server admits 2 of them,
                           statuses [200,200,429,409,409,409] — one 429 wedged the lane.
                           current posts [0,1,2,2,3], statuses [200,200,429,200,200], 0 x 409.
  defect 1  queue 429      current posts [0,1] with statuses [429,200] and droppedFrames=1;
                           resending here would arrive as 0 against an expected 1 and 409.
  defect 1  serialization  pre-branch has 2 posts in flight at once; released out of order the
                           server receives [1,0] -> [409,200] and admits 1 frame.
                           current has exactly 1 in flight; server receives [0,1] -> [200,200].
  defect 1  409 resync     current: [409] then, on the next worklet frame, [0,4,5]/[409,200,200].
  defect 2  clean stop     pre-branch stop() issues only /stop. current issues /heartbeat with
                           state "stopped" then /stop.
  defect 2  track ended    pre-branch reports state "capturing"/failure_code null and keeps
                           posting the dead lane (server admits it). current reports
                           "failed"/"browser_track_ended", leaves the peer "capturing", and
                           stops posting that lane.
  defect 3  lane loss      pre-branch has no replaceLane at all; every frame carries
                           device_epoch 1 / discontinuity false and the server's
                           current_device_epoch never moves. current: epoch 2 + discontinuity
                           true, accepted; the same bump WITHOUT discontinuity is rejected
                           409 v2_epoch_discontinuity_required (so the flag is load-bearing).
  defect 4  sample rate    context 48000 / descriptor 16000: pre-branch ships sample_rate 16000
                           and capture_timestamp_ns 500000 ns; current ships 48000 and
                           166667 ns.
  defect 5  preflight gate 5e-5 dither: pre-branch creates a session on silence; current
                           refuses, and still admits a real 0.5 signal afterwards.

pinned to the production ingress by probe 2, but it is still a fake: it does not exercise
FastAPI routing, auth, the mixer, or the tape.
