# Iteration 17 — attended-run poller cursor recovery

## Question

Can the shipped poller recover when a snapshot cursor is answered `unchanged` even though
the server's independent v2 ingress facts prove it has accepted more audio?

## Deterministic incident replay

The regression test mirrors the attended incident's cursor and terminal versions:

1. A full snapshot is rendered at version 153 with both v2 lanes at 153 accepted samples.
2. `since_version=153` returns `{snapshot: null, unchanged: true}` while both lanes have
   advanced to 294 accepted samples and events remain empty.
3. The required uncursored reread returns the closed snapshot at version 332.

Before the production change, the replay failed because `onTerminal` was never called:

```
expected "vi.fn()" to be called with arguments: [ 'Session closed.' ]
Number of calls: 0
```

The repair records the cumulative v2 accepted-sample total. It resets the snapshot cursor to
zero only if that total advanced during an `unchanged` response. This uses server-owned,
monotonic progress rather than a new polling-count or time threshold.
