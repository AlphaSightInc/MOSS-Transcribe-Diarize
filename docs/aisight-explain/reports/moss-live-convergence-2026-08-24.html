Implementation-ready architecture explainer

Make MOSS live mode fast now and correct later

How do short, rolling, and terminal time windows cooperate without duplicating words, corrupting speakers, or letting a long meeting grow slower?

Plan against codebase · evidence through 2026-08-24 · aisight-explain v20260821

Technical plan: implementation-ready Owner authorization: still required Cross-review: Claude + Codex, 4 rounds

Executive brief

Use three hearings of the same retained audio, each with a different job. A short MOSS request gives immediate provisional words; a longer overlapping MOSS witness replaces them with a monotonic rolling transcript; a stop-time file-style pass produces the final surface.

  1. The 2.5-second cap is a responsiveness and bounded-work policy, not a model requirement. It is also where most word damage occurs.
  2. A 10–15 second witness fixes seam words by owning only an interior region. Context is heard but not necessarily published.
  3. One-second preview is viable only after the witness owns speaker evidence. Text compensation was measured; speaker compensation is not yet good enough.
  4. The plan is technically executable but review-gated: E0 through E4 each need measured evidence and explicit authorization.
Confirmation. Claude–Codex cross-review completed in four rounds with no remaining technical defect. “Implementation-ready” means a junior engineer can execute the gated plan; it does not replace unsigned owner decisions about text-finalization authority and complete tape retention.

Part I · Mental model

Start with one audio clock and five primitives

The goal and the present system

MOSS live mode has one fact that controls the design: MOSS does not expose a separate automatic speech recognition (ASR) lane here. A single MOSS request jointly returns words, timestamps, and within-request speaker labels. WebRTC voice activity detection (VAD) sits before it and decides where to cut audio. WeSpeaker sits after it and maps request-local labels such as S01 to stable meeting identities.

mixed PCM → WebRTC VAD / endpoint → one bounded MOSS request
          → words + timestamps + local speaker turns
          → WeSpeaker identity → published span

The mission is not “make every first guess perfect.” The user accepts temporary mistakes. The mission is: publish quickly, improve predictably, then settle once.

Latency and accuracy do not need one compromise window if the transcript has more than one explicit authority.

Five primitives are enough to reconstruct the design

P1 · Audio position
An exact sample number on one 16 kHz clock. Sample 40,000 is 2.5 seconds.
P2 · Request window
The audio interval sent to one fresh MOSS decode. Longer windows give more context but become eligible later.
P3 · Owned region
The smaller interval whose output a request may publish. Edge audio can be heard as context while another request owns its words.
P4 · Authority
Which result wins for an interval: provisional, rolling canonical, or terminal final.
P5 · Clock
The latency question: first publication, later correction, or finalization after stop.

One sentence, heard three times

Follow a Simulated specimen derived from measured seam behavior: Ana says “the difference between the stock market and the bond market”. A hard cap lands inside between. The exact phrase is illustrative; the error concentration and correction measurements are recorded evidence.

1 · Short hearing publishes quickly

Audio: the difference bet │ ween the stock market …

Requests: [ 0.0 ───── 2.5 ] [ 2.5 ───── 5.0 ]

Provisional: “the difference … in the stock market”

Each request starts fresh. Neither side hears the whole cut word. The UI may show the guess because low latency is valuable.

2 · Rolling witness re-hears both sides

Witness: [ left context │ owned middle │ right context ]

Heard: “the difference between the stock market and …”

Revision: replace the next owned interval; advance frontier →

The witness replaces one contiguous interval beginning at the frontier. This prevents duplicates, holes, and oscillation.

3 · Terminal hearing settles the export

After stop: retained tape → 150 / 120 s windows

Final: “the difference between the stock market and the bond market”

Authority: terminal final replaces the complete rolling surface once

Portal and export use the same final surface. Failure leaves the best rolling surface without a false final claim.

Stage 1 of 3

What most people get wrong

MOSS has three independent ASR, VAD, and diarization lanes we can vote.

WebRTC VAD is external, one MOSS request jointly emits text/timestamps/local speakers, and WeSpeaker reconciles identity afterward. Another “ASR view” is another MOSS request over retained audio.

A long meeting slows because MOSS prefills the whole transcript history.

Current live requests carry no meeting history. The seam failure repeats; it does not accumulate. Bounded witnesses preserve that property.

More overlap automatically means better output.

Only overlap plus one-owner reconciliation helps. A five-second decode at every seam spent more and worsened WER.

One-second preview is proven once rolling text reaches the same WER.

Text reached .146 from both bases, but one-second rolling DER stayed .292 versus .114 on the 2.5-second base.

Part II · Time-window engine

Cut, re-hear, then transfer authority

The short endpoint — why 2.5 seconds exists

The endpoint turns an endless stream into bounded requests. It closes on silence, flush/stop, or the deployed 40,000-sample hard cap: 40,000 ÷ 16,000 Hz = 2.5 seconds.

The mechanism, walked

WebRTC VAD reports speech on ordered, gap-free observations. The endpoint accumulates audio. Enough silence closes naturally. Continuous speech crossing the hard boundary emits hard_cap, resets speech state, and starts the next exact partition.

Confirmed endpoint rule · app/live_endpoint.py
if hit_hard_cap:
    spans.append(self._emit_until(end, "hard_cap"))
    self._reset_speech_state()

def _next_hard_boundary(self):
    return self._open_start + self.config.hard_cap_samples

Why it is built this way

Pressure: continuous speech can delay publication and grow requests. Choice: cap at 2.5 seconds. Alternative: wait only for silence. Trade-off: bounded latency/memory versus arbitrary speech seams.

Measured failure

More than 0.5 seconds from a seam, live WER was .082 versus file .072. Near a seam, live was .373 versus file .088. Straddling bigrams survived 48.5% versus 89.4% inside spans.

The short window is a publication deadline, not the final unit of truth.

Rolling witness — hear wide, publish narrow

The witness sends a longer retained-audio window through the same MOSS model, then grants it authority over one central interval.

The mechanism, walked

  1. Retain bounded mixed PCM on the absolute sample clock.
  2. When enough right context exists, enqueue one rolling MOSS request.
  3. Map relative word/speaker times back to absolute samples.
  4. Reconcile overlap without reference truth.
  5. Accept only a proposal beginning at the current frontier and advancing it.
  6. Refuse stale results; never move the frontier backward.

Invariants

One owner per interval; ordered non-overlapping segments; forward-only frontier; immutable base commits; stale work changes nothing; rolling PCM bounded to 2 × W seconds.

Why rolling, not one request per seam

Measured 10 / 5 rolling reached WER .1289, recovering 74% of the gap to file. Five seconds at every seam worsened WER to .2298. The lever is few, wide owned regions, not maximum decode count.

Every correction must answer: what did this request hear, and what exact interval may it own?

Transcript authority — three states, one visible surface

A result can be fast, corrected, or settled. Those are states, not styling adjectives.

1 · Provisional

Short result. Fastest. May be wrong. Immutable audit history, but not permanently visible.

2 · Rolling canonical

Longer witness owns a prefix through the frontier. Accepted revisions extend it monotonically.

3 · Terminal final

Complete retained tape, file-style windowing. Replaces the full effective surface once.

Current state and proposed split

Today CanonicalCommit.transcript is immutable and revised_transcript means “same words, changed labels.” Preserve that history; add text_revision_version, canonical_through_sample, and effective_transcript. Word and label revisions validate different facts.

Failure behavior

Rolling failure leaves the visible surface unchanged. Stale work is refused. Terminal failure keeps capture successful and preserves the best rolling surface with a failed finalization status.

Immutable history answers “what was first published”; authority answers “what should the user trust now.”

Part III · Trade-offs

Latency, compute, speakers, and long meetings

Three latency clocks — never blend them

“Latency” is ambiguous until start and end events are named.

L1
First-word age = provisional publication − first spoken-word audio start. Includes capture, queue, decode.
L2
Correction age = changed rolling publication − provisional publication of the replaced region.
L3
Finalization lag = final publication − meeting stop.
3.04 smean first-word age · 2.5 s base
1.00 smean first-word age · 1 s base
3.69–4.65 smean correction after provisional
1.86 smean finalization after stop · 60 s cases
≤ 2.0 sproposed p95 G5 first-word gate
≤ 6.0 sproposed p95 G6 correction gate

Browser capture and paint are a fourth diagnostic, reported beside these clocks—not silently folded into or removed from user-perceived delay.

Decision

A 1-second base can improve L1 only if E3 proves timely L2 correction and witness-owned speaker evidence. Until then, keep 2.5 seconds.

MOSS/vLLM exposes no reusable encoder or decoder state across requests. Each overlap re-encodes and re-decodes. Reusable assets are retained PCM, a completed witness across text/speaker strategies, exact-interval WeSpeaker embeddings, and accepted authority state. Neural-state reuse needs a later model-server architecture change.

Speaker evidence — the longer witness must own it

Correct words do not guarantee correct speakers. MOSS local S01 is meaningful only inside one request.

The speaker path

  1. The longer witness emits local speaker turns.
  2. Only its owned middle selects PCM evidence.
  3. WeSpeaker embeds each exact local-speaker interval—not a mixed-speaker full window.
  4. The meeting album maps embeddings to stable identities.
  5. The revision carries witness-owned words and speaker assignments.
.457DER · isolated 1 s
.292DER · rolling words on 1 s anchors
.114DER · rolling words on 2.5 s anchors

Can five-phase views avoid 5× compute?

Yes as an uncertainty router; no as blanket processing. Natural rolling overlap already gives multiple boundary views. If they agree, publish without another view. If they disagree, add phase-shifted views only there and cache exact-interval embeddings. If 10% of regions need four extra views, regional extra work is roughly 0.10 × 4 = 0.40 of one blanket pass, not four whole-meeting passes.

Why voting is not authority

Sibling evidence found all 20 phase views could agree on a wrong merged handoff. Plurality or 4-of-5 is only uncertainty. It cannot override owned evidence unless a MOSS prototype improves accuracy and targeted extra work stays within 40% of a blanket view.

Use disagreement to decide where to spend compute; never treat agreement alone as proof.

Terminal windows — 150 seconds heard, 120 seconds advanced

Reach file-mode quality without sending the entire growing meeting in one request.

Why history stays bounded

At 60 minutes, each terminal request still hears at most 150 seconds. Window count grows linearly; per-request prefill does not. Rolling memory remains separately bounded to 2 × W.

Why wait until stop

Terminal WER .104 matched paired file mode on the 60-second trio, but future context cannot exist live. This serves “settled,” not “fast.”

Owner decision required. E4 needs permission to retain complete mixed audio and an ADR granting terminal re-ASR authority. The technical plan is ready; authorization is not.

Part IV · Implementation

A measured sequence with stop gates

Review-gated roadmap

The plan is implementation-ready: modules, seams, prototype commands, corpora, metrics, queue/memory bounds, and exit gates are specified and cross-reviewed. It is not implementation-authorized: owner approvals and the phase ledger remain unsigned.

  1. Measurement integrityRepair replay reconstruction, preserve raw decode disposition, establish evaluator v2. Later metrics stay blocked until honest.
  2. Bounded malformed-output salvageComplete only a safely missing closing timestamp. No extra GPU. Stop if refusal text or silence is promoted.
  3. Rolling text on 2.5 s basePrototype 10/10 and 15/10 against 10/5; choose by quality then work. Ship monotonic word authority only after gates pass.
  4. Witness-owned speakers; optional 1 s previewProve speaker correction first. Only then test one-second provisional output. Failure retains 2.5 s.
  5. Terminal convergenceReuse 150/120 file windowing over authorized retained tape. Require file-paired quality and duration/concurrency proof.
Prototype rule. Every medium/high-risk policy produces measurements before production code. A failed gate stops that phase; it does not trigger compensating complexity.

Rebuild kit — decisions in order

A new team can reconstruct the architecture from these choices.

  1. What is the canonical coordinate?

    Multiple decoders must name the same audio without drift.

    Use absolute 16 kHz sample intervals for windows, ownership, proposals, and frontier.

    Floating seconds per component — rejected; rounding makes ownership ambiguous.

    Revisions overlap or leave holes.

  2. Who publishes first?

    Feedback is needed before high-quality context exists.

    Short output is provisional and retained as immutable base history.

    Wait for witness — credible but less responsive.

    The UI feels slow or weak output is mistaken for final.

  3. How does a witness replace words?

    Overlaps can duplicate, omit, or oscillate.

    One owned region begins at the frontier and advances it.

    Arbitrary patches — rejected; ownership becomes global.

    Text repeats or disappears at joins.

  4. Who owns speaker evidence?

    One-second labels and mixed context collapse voices.

    The witness embeds only its local-speaker PCM inside its owned region.

    Inherit short identities — measured text passes while DER remains poor.

    Correct words carry the wrong person.

  5. How is a meeting settled?

    Rolling lacks future context; entire history cannot fit one request.

    After stop, use 150 s windows / 120 s stride with midpoint ownership.

    One growing request — rejected by bounded context.

    Long files fail or portal/export disagree.

Part V · Boundaries

What is proven, projected, and blocked

Known limits

  • Confirmed: seam loss dominates the measured word gap on three referenced 60-second interviews.
  • Confirmed: rolling10 improves text from both 2.5 s and 1 s bases to WER .146; independent lexical stitch reached .129.
  • Confirmed: 1 s speaker performance remains worse; witness-owned speaker authority is unimplemented/unmeasured.
  • Confirmed: terminal150 matches paired file WER on the three 60-second cases.
  • Unmeasured: selected 10/10 or 15/10 schedule, two sessions, browser paint, long DOM cost, and long terminal behavior.
  • Projected: uncertainty-routed phase views reduce blanket compute; MOSS accuracy benefit is not proven.
  • Scorer caution: TBSA/DER can improve through wider timestamp extent without better words. WER and recall remain primary pending evaluator v2.
  • Governance block: signatures, text-finalization ADR, and complete mixed-tape retention authority remain open.
Do not overclaim. This is an implementation-ready, review-gated architecture—not a claim that production exists, one-second preview is promotable, or two-session capacity has passed.

Part VI · Shared language

Minimal glossary

Audio clock
The one absolute 16 kHz sample coordinate.
Endpoint
The policy that turns accumulated live audio into a bounded request.
Hard cap
Maximum endpoint span; currently 40,000 samples or 2.5 seconds.
Request window
All audio sent to one fresh MOSS decode, including context it may not own.
Stride
How far the next window start advances. Window ÷ stride approximates repeated work.
Owned region
The exact interval whose words and speaker evidence one result may publish.
Witness
A longer MOSS request that re-hears provisional regions and proposes correction.
Rolling frontier
The first sample not yet owned by rolling authority. It moves forward only.
Authority
The output allowed to win: provisional, rolling canonical, terminal final.
Effective transcript
The visible rolling prefix plus provisional suffix, or terminal final surface.
Local speaker
A label such as S01 meaningful only inside one MOSS request until reconciled.
GPU real-time factor
GPU inference seconds divided by meeting seconds; lower is better.
Word error rate (WER)
Substitutions, deletions, insertions divided by reference words; lower is better.
Diarization error rate (DER)
Speaker-time error from missed speech, false speech, and speaker confusion; lower is better.
TBSA
Composite transcript/speaker score; useful for continuity but currently extent-sensitive.
